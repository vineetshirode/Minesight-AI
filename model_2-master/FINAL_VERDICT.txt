1. Lag Features Are Correct
   Implementation uses pandas shift(1) which creates:
   - Production_Lag_1[t] = Actual_Production[t-1]
   This correctly references PREVIOUS month only.

2. Rolling Features Are Safe
   Implementation chains operations correctly:
   - First: shift(1) to get only past values
   - Then: rolling(3) on shifted values
   Prevents inclusion of current or future months.

3. NaN Handling Is Sound
   January 2022 has NaN for Production_Lag_1 (no Dec 2021 data)
   Filled with mean of training period Production_Lag_1 values
   This prevents bleeding of test data into training statistics.

4. Train/Test Split Is Clean
   No overlap in time: Dec 2024 (train max) before Jan 2025 (test min)
   No rows exist outside their intended sets
   Chronological ordering preserved.

5. Cross-Validation Is Proper
   Uses TimeSeriesSplit with 5 folds
   Each fold: earlier training dates, later validation dates
   Simulates true predictive scenario

6. Feature Engineering Respects Time
   All per-mine statistics computed within mine groups
   All temporal features (Month, Quarter) are deterministic
   All derived features use only available information
